## Required gates for every implementation batch

1. Declare a versioned bounded input/output/units/support/CRS/datum contract and explicit unsupported cases before coding transformations. Unknown metadata stays unknown; retain original assets and provenance.
2. Implement a public API plus the relevant file reader/writer. Save→relocate→read→write→read is an actual operation on new output paths, with exact supported metadata/assets and separately reported numerical or semantic differences.
3. Execute authored valid/invalid examples, adversarial format/budget/failure cases and independent mathematical/physical checks appropriate to the algorithm. New solver integrations execute the actual permitted versioned engine. A skipped solver check does not count as passed.
4. Connect supported objects to the shared package/workspace without losing prior supported data. A UI field that displays a value does not establish complete editing, interpretation or original behavior.
5. Run affected regressions first and retain truthful selected-module evidence, then refresh exact status source/test identities and run the complete strict suite plus fresh execution examples. Preserve failed receipts and diagnose the exact cause before rerunning.
6. Record local PARTIAL scope only from retained implementation and actual execution evidence, then publish the original code, authored examples, status changes and sanitized receipts to the existing PR after strict regression. Planning, import success, a plotted shape or a green counter never completes a whole feature or the product; publication remains a separate checkpoint gate.
